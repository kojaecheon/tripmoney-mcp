# TripMoney 목업 시연 대본

노트북에서 목업 파일을 직접 열어 보여주는 15분 시연 기준이다. 실제 서비스가 아니라 합성 데이터로 움직이는 화면 설계 목업이라는 점을 시작할 때 한 번 말해 둔다.

## 시연 전 준비 (5분)

1. Chrome에서 `docs/design/mockups/index.html`을 연다. 서버는 필요 없다. 파일을 더블클릭하거나 주소창에 파일 경로를 붙여 넣으면 된다.
2. 인터넷이 연결되어 있어야 서체(Pretendard, Fraunces, Space Mono)가 내려온다. 오프라인이면 시스템 한글 서체로 대체되며 배치는 그대로다.
3. 브라우저 확대 배율을 100%로 두고 다른 탭은 닫는다. 화면 상단의 검은 이동 막대는 목업 전용이며 실제 화면 설계의 일부가 아니라고 미리 말한다.
4. 참여자 공유와 총무 검토는 모바일 우선 화면이다. 개발자 도구의 기기 툴바(iPhone 폭 375px)를 미리 켜 두거나, 창 폭을 좁혀서 보여준다.
5. 화면 안의 상호작용(승인, 이의 제기, 검수 승인)은 저장되지 않는다. 새로고침하면 처음 상태로 돌아가므로 리허설 뒤에 새로고침해 둔다.
6. 파일에서 스크립트가 막히는 브라우저라면 터미널에서 다음 명령으로 띄우고 `http://localhost:8123/index.html`을 연다.

```bash
python3 -m http.server 8123 --directory docs/design/mockups
```

## 핵심 메시지 (시연 내내 반복)

- 정산이 끝나도 근거가 남는다. 지출마다 영수증 근거 태그, 환율마다 출처와 시각, 정산마다 버전이 붙는다.
- 스탬프는 사람의 행위에만 찍힌다. 총무 승인, 참여자 확인·이의·철회, 내부 QA, 최종 잠금.
- 돈과 계좌를 다루지 않는다. 송금은 참여자가 직접 하고 계좌번호는 어떤 화면에도 없다.

## 흐름과 클릭 순서

### 1. 허브 (30초)

- 네 화면과 열한 장면을 한눈에 보여준다. "고객이 보는 랜딩, 총무가 쓰는 검토, 참여자가 보는 공유, 직원이 쓰는 운영자 워크벤치"라고 설명한다.
- 랜딩 카드의 `intake_on`을 누른다.

### 2. 공개 랜딩 `landing.html?state=intake_on` (3분)

- 헤드라인 "근거가 남는 해외여행 최종 정산"과 오른쪽의 완성된 정산 결과(보딩패스, 태그가 붙은 지출, 총무 승인 스탬프)를 짚는다. "이 세 가지 서류 요소가 모든 화면을 관통한다"고 말한다.
- 특징 카드 다섯 장을 훑는다. 각 카드 안에 실제 화면 조각이 들어 있다는 점을 강조한다.
- 절차 밴드에서 레일의 단계 위에 마우스를 올려 종료 조건 말풍선을 보여준다. "검수" 단계의 SLA 시작 표시를 짚는다.
- 가격 두 셀을 비교한다. 마감 대행형이 반전 색으로 강조되어 있고 항목 순서가 같다는 점을 말한다.
- 적격·제외 조건과 고지 네 칸을 짧게 보여준다. "검토 전 문구" 표시는 법률 검토 전이라는 뜻이다.
- 신청 폼에서 빈 채로 "신청 보내기"를 눌러 오류 문구를 보여주고, 이메일을 넣고 동의에 체크한 뒤 다시 눌러 접수 메시지를 보여준다.
- 시간이 남으면 이동 막대에서 `intake_off`를 눌러 접수 비활성 변형을 보여준다.

### 3. 총무 검토 `review.html?state=awaiting_organizer` (4분)

- 상단 레일이 "탑승 승인"에 있음을 짚는다. 정산 결과 표(낸 돈, 부담, 순액)와 송금 제안 보딩패스를 보여주고 "카톡 문구 복사"를 눌러 복사 알림을 보여준다.
- 근거 구획에서 지출 12건의 태그(원본 검수, OCR 미검수, 수동 입력)와 환율 출처 두 건(자동, 수동 사유)을 짚는다.
- 잠금까지 남은 조건 세 개가 모두 대기인 것을 보여준다.
- 수정 이력에서 v1과 v2, 남은 수정 묶음 횟수를 보여준다.
- "이 버전 승인"을 누른다. 총무 승인 스탬프가 찍히고 참여자 현황이 무응답 4로 열리며 공유 구획이 나타난다.
- 이동 막대에서 `participant_review`로 옮긴다. 승인 2, 이의 1, 무응답 1과 이의 사유를 보여주고, 잠금 요청 버튼이 비활성인 이유를 읽는다.
- "카카오 공유 미리보기"를 눌러 여행명, 버전, 기준 환율, 송금 제안만 들어간다는 점을 보여주고 Esc로 닫는다.
- `finalized`로 옮긴다. 잠금 스탬프 v2와 내부 QA 스탬프, 원본 삭제 태그, 수정 요청 폼이 사라진 것을 보여준다.

### 4. 참여자 공유 `share.html?state=notice` (3분, 375px 폭)

- 고지 화면의 여섯 항목과 세 선택지를 보여준다. "참여자 연락처를 받지 않으니 링크는 총무가 직접 보낸다"고 말한다.
- "계속"을 누른다. 본인 몫(낸 돈, 부담, 순액)과 본인이 관련된 송금만 보인다는 점, 다른 참여자의 지출 상세가 없다는 점을 강조한다.
- 근거 구획(환율 기준, 반올림, 원본 검수 건수, 마지막 수정, 검토창 마감)을 읽는다.
- "이의 제기"를 눌러 빈 사유로 보내 오류를 보여주고, 사유를 적어 보내면 이의 스탬프와 철회 링크가 나타나는 것을 보여준다. 하단의 "무응답은 승인이 아닙니다" 문장을 짚는다.
- 이동 막대에서 `expired`를 눌러 만료 안내(여행명 없음)를 보여준다.

### 5. 운영자 워크벤치 `operator.html?state=queue` (4분, 데스크톱 폭)

- 큐가 SLA 잔여 시간 순으로 정렬되고 일시정지 케이스가 마지막에 오는 것을 짚는다.
- C-013을 눌러 레일의 일시정지 배지와 "상세 목업 없음" 안내를 보여준 뒤 다시 C-014를 누른다.
- "검수 열기"를 눌러 `case` 장면으로 간다. 체크포인트(확인 2, 차단 3)와 차단 사유, 자료수집 체크리스트를 보여준다.
- 지출 목록의 수하물 태그를 보여주고, 영수증 검수 3열(원본 자리 표시, OCR 추출, 수정·승인)에서 통화가 THB로 확정된 것을 확인한 뒤 "검수 승인"을 누른다. 검수자 줄에 승인 시각이 기록된다.
- 환율 출처와 정산 버전·불변식 8개(통과 3, 실패 2, 대기 3)를 보여준다. 실패 항목의 "원인 지출 보기" 링크를 짚는다.
- 내부 QA 폼에서 상태 "확인"과 짧은 의견을 넣어 "의견 추가"를 누르면 내부 QA 스탬프가 찍힌다. "잠금 실행"이 비활성인 이유를 읽는다.
- 하단의 접이식 세 패널(공유·폐기, 작업시간·비용·환불, 보유·삭제·사고중단)을 펼쳐 보여준다.
- 상단 "리드" 탭을 눌러 마스킹된 연락처만 보이는 것을 보여준다. "설정"은 준비 중 표시다.

### 6. 마무리 (1분)

- 허브로 돌아와 "네 표면이 같은 서류 언어(레일, 보딩패스, 스탬프, 태그)를 쓴다"는 문장으로 닫는다.
- 다음 단계(실제 화면 구현, 카카오 채팅 연동)는 별도 계획이라고 말한다.

## 질문이 나올 만한 한계

- 데이터는 방콕 4박 한 세트뿐이고 저장되지 않는다. 새로고침하면 초기 상태로 돌아간다.
- 로그인, 결제, 실제 영수증 이미지, 실제 환율 조회는 없다. 영수증 원본은 회색 자리 표시다.
- 운영자 이의 목록은 구획과 빈 상태만 보인다. C-014가 참여자 검토 전 단계라 이의 행 데이터가 없다.
- 케이스 상세는 C-014만 제공한다. 다른 케이스는 안내 문구만 나온다.
- 실제 서비스(카카오 채팅 + DB)는 이 목업과 별개이며, 현재 프로덕션 DB가 비활성 상태라 라이브 시연은 되지 않는다.

## 문제가 생기면

- 화면이 비어 보이면 새로고침한다. 그래도 비면 위의 서버 명령으로 띄워서 연다.
- 서체가 다르게 보이면 인터넷 연결 문제다. 배치와 동작은 같으니 그대로 진행한다.
- 모바일 폭이 필요할 때 개발자 도구를 열기 어려우면 창 폭을 손으로 좁히면 된다. 레일은 옆으로 스크롤된다.
